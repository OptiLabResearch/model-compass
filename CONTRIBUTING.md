# Contributing to Model Compass

Thank you for helping improve the project. Small, focused pull requests are welcome; open an issue first for large changes, breaking changes, or major changes to data methodology.

## Set up a fork

1. Fork `OptiLabResearch/model-compass` on GitHub.
2. Clone your fork and create a branch:

```bash
git clone https://github.com/YOUR-USERNAME/model-compass.git
cd model-compass
git checkout -b fix/short-description
python3 -m http.server 8000 --directory public
```

3. Open [http://localhost:8000](http://localhost:8000).

The project has no application dependencies or build step. Python 3.12+ and Node.js 20+ are used by the checks.

## Make and verify changes

Keep deployable files under `public/`. Keep refresh tooling, caches, history, and contributor documentation outside it.

Before opening a pull request, run:

```bash
python3 -m py_compile scripts/*.py
python3 scripts/validate_site.py
node --check public/assets/nav.js
node --check public/assets/models.js
node scripts/test_browser_security.mjs
```

For UI changes, also check search, creator filters, presets, numeric filters, comparison, sorting, theme switching, and shared hash links in light and dark modes. Include before/after screenshots.

## Data changes

Normal UI contributions do not require an API key. To intentionally refresh generated data, obtain your own Artificial Analysis key and place it in an ignored `.env` as described in the README. Never commit, print, or share that key.

Generated changes should explain why the refresh was run and include `public/data/models.json`, `data/enrichment_cache.json`, and the matching history snapshot together.

## Pull requests

- Keep changes focused and preserve unrelated work.
- Explain the user-visible result and verification performed.
- Do not weaken the CSP, public-directory allowlist, URL allowlist, data validation, or immutable Action pinning without a documented security reason.
- Do not add dependencies when browser or Python standard-library features are sufficient.
- Do not include secrets, personal data, workstation paths, editor state, or generated bytecode.

Security vulnerabilities must be reported privately through [SECURITY.md](SECURITY.md), not through a public issue.
